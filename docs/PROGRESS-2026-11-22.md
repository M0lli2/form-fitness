# Form 0.3.4 작업 기록 (2026-11-22)

모리 님의 실사용 피드백 4건(IMG_9256 · IMG_9257 · IMG_9258)을 `v0.3.4`에 반영했습니다.
이 문서는 나중에 다른 도구(ChatGPT 등)로 이어서 작업할 때 누락이 없도록, 무엇을 왜 어떻게 바꿨는지와
검증 방법·남은 일을 파일·함수 단위로 남깁니다.

## 1. 세트 입력 후 이후 세트 자동 반영 (IMG_9256)

**증상** — `준비 중 · 0:00` 상태에서 1·2세트에 `22 kg`을 입력했는데 3·4세트가 `0`으로 남았습니다.

**원인** — `src/core.mjs`의 `editSets(sets, index, patch)`가 `index === 0`일 때만 뒤 세트로 값을 전파하고,
`index !== 0`이면 `set.edited = true`만 세우고 끝났습니다. 2세트 이상을 고치면 그 세트만 바뀌었습니다.

**수정** (`src/core.mjs`)

- 전파 대상을 `index`와 무관하게 `sets.slice(index + 1)`로 바꿨습니다. 조건은 그대로
  `!next.done && !next.edited`입니다. 이미 완료한 세트와 사용자가 직접 고친 세트는 덮어쓰지 않습니다.
- 전파하는 값은 `SET_VALUE_KEYS = ['weight', 'reps', 'seconds', 'distance', 'rpe']`로 넓혔습니다.
  기존에는 중량·횟수만 이어졌고, 시간·거리·RPE 입력은 뒤 세트로 전파되지 않았습니다.
- `index !== 0`인 세트를 고치면 그 세트는 `edited = true`로 남아, 앞 세트를 나중에 고쳐도 값이 유지됩니다.
  `index === 0`은 전파 기준값이므로 `edited`를 세우지 않습니다(첫 세트를 다시 고치면 뒤 세트가 다시 따라옵니다).

**입력 누락 보완** (`src/App.tsx`의 `Numeric`)

- 기존에는 `onEndEditing`에서만 값을 커밋해서, 키보드를 내리거나 다른 버튼을 누르는 순간 값이 사라질 수 있었습니다.
- 이제 `onBlur`, `onEndEditing`, `onSubmitEditing`, 키보드 숨김(`Keyboard.addListener('keyboardDidHide')`),
  입력이 0.7초 멈췄을 때의 지연 커밋까지 다섯 지점에서 값을 확정합니다.
- 입력 중에는 부모 값이 바뀌어도 사용자가 쓰던 글자를 덮어쓰지 않고, `sent` ref로 같은 값을 두 번 저장하지 않습니다.
- 빈 칸은 입력 중일 수 있으므로 지연 커밋에서는 되돌리지 않고, 포커스가 빠질 때만 이전 값으로 복구합니다.
- `준비 중`과 `진행 중` 화면이 같은 `Numeric`을 쓰므로 두 상태 모두 같은 규칙으로 동작합니다.

**테스트** — `tests/set-suggestion.test.mjs`

- `준비 화면에서 2세트에 입력한 값이 3·4세트로 이어진다(IMG_9256)`: 4세트에서 2세트를 고치면 3·4세트가 따라오고,
  뒤 세트를 직접 고친 뒤에는 그 세트를 건드리지 않으며, 시간·거리·RPE도 전파되는지 확인합니다.
- 기존 `직접 고친 세트와 이미 끝낸 세트는 자동 반영으로 덮어쓰지 않는다`를 새 규칙에 맞게 갱신했습니다
  (2세트를 고치면 3세트가 따라오는 것이 이제 정상 동작입니다).

## 2. 추천 구성(루틴) 진입 시 자동 시작 방지 (IMG_9257 · IMG_9258)

**증상** — 홈(`오늘`)이나 `루틴` 탭에서 추천 구성·루틴을 누르면 곧바로 타이머(`진행 중 · 0:02`)와 집중 운동 화면이
시작됐습니다. 루틴 카드의 `▶`도 같았습니다.

**원인** — `src/App.tsx`의 `start(name, ids)`가 `makeSession`으로 즉시 세션을 만들고 `setFocused(true)`를 호출했습니다.

**수정**

- `src/core.mjs`에 `prepareSession(name, exercises, history)`를 추가했습니다.
  `makeSession` 결과에 `preparing: true`를 붙인 것으로, 자유 운동의 `prepareWorkout()`과 같은 흐름입니다.
- `start(name, ids)`는 이제 `prepareSession`으로 세션을 만들고 `setFocused(false)`로 들어갑니다.
  타이머는 상단 `운동 시작`을 눌렀을 때 `startPreparedWorkout()` → `beginPreparedWorkout()`이 시작합니다.
  `beginPreparedWorkout`이 `startedAt`을 누른 시점으로 다시 잡으므로 준비 화면에 머문 시간은 운동 시간에 들어가지 않습니다.
- 이 경로를 쓰는 모든 진입점이 함께 바뀌었습니다.
  - 홈·루틴 탭의 루틴 카드 `▶` (`RoutineCard`)
  - `어떤 운동을 할까요?` 시트의 루틴 버튼과 새 `자유 운동으로 시작` 버튼
  - 운동도감의 `이 운동 기록하기`(진행 중인 운동이 없을 때)
  - 기록 상세의 `같은 구성으로 다시 운동`
- 홈 추천 카드 문구를 `루틴으로 준비하기`로 바꾸고, 추천에 포함한 루틴이 하나도 없으면 자유 운동 준비로 안내합니다.
- 준비 중에는 상단 상태 줄 왼쪽에 세션(루틴) 이름을 함께 보여 줍니다. 이름은 `numberOfLines={1}`로 한 줄만 쓰고
  오른쪽에 기존 `준비 중 · 0:00`을 그대로 두어 화면 높이가 바뀌지 않습니다.
  (처음에는 본문에 안내 카드를 넣었지만, 세트 입력 칸이 아래로 밀려 Android 여정의 필드 탭이 빗나갔습니다.
  본문은 0.3.3과 동일하게 두고 이름만 상태 줄로 옮겼습니다.)

**테스트** — `tests/preparation.test.mjs`

- 루틴으로 들어가면 `preparing`이고, 몇 분이 지나도 `workoutElapsedSeconds`가 0이며, 준비 중에는 일시정지·종료가 되지 않고,
  `운동 시작` 시점이 기록의 `startedAt`이 되는지 검증합니다.
- 준비 세션에도 이전 기록의 무게·세트 수가 채워지는지, `자유 운동` 준비와 같은 흐름인지 확인합니다.

## 3. 집중 운동 하단 컨트롤 박스 ON/OFF (IMG_9257)

**증상** — 집중 운동 화면 하단의 큰 컨트롤 박스(목표 칩·휴식 조절·세트 완료·+ 세트 추가·전체 운동 목록)가 화면 절반을 가려
뒤쪽 추천 문구와 안내를 가렸습니다.

**수정** (`src/ui-v2/FocusedWorkout.tsx`)

- `controlsOpen` 상태를 추가했습니다. 기본값은 펼침입니다.
- 펼친 상태: 박스 맨 위에 `컨트롤 숨기기 ▾` 토글(`accessibilityLabel="컨트롤 숨기기"`).
- 접힌 상태: 큰 박스를 감추고 `styles.compact` 한 줄만 남깁니다.
  `컨트롤 열기 ▴` 토글, 작은 `세트 완료`(모든 세트를 마쳤으면 `다음 운동`) 버튼, 휴식 중이면 남은 시간만 표시합니다.
  접힌 줄은 `paddingVertical 9`, 버튼 `minHeight 44`로 최소 터치 크기를 지키면서 배경을 가리지 않습니다.

## 4. 내 루틴 추천 포함 설정 + 기존 추천 구성 수정·삭제

**수정**

- `src/types.ts`의 `Routine`에 `recommended?: boolean`을 추가했습니다. 없는 값은 `포함`으로 봅니다(하위 호환).
- `src/exercises.json`의 기본 루틴 4종(`full`·`upper`·`lower`·`home`)에 `"recommended": true`를 명시했습니다.
- `src/core.mjs`에 루틴 도우미를 추가했습니다.
  - `normalizeRoutine(input)`: 이름 필수(40자 제한), 운동 1개 이상, 중복 제거, 설명 기본값, `recommended !== false`.
  - `saveRoutine(routines, routine)`: 같은 ID는 교체하고 맨 앞으로. 기본 루틴도 같은 경로로 수정됩니다.
  - `removeRoutine(routines, id)`, `setRoutineRecommended(routines, id, included)`, `recommendedRoutines(routines)`.
  - `validateBackup`이 루틴의 `recommended`가 boolean이 아니면 거절합니다.
- `src/App.tsx`의 `RoutineForm`은 이름 직접 입력, 한 줄 설명, `추천 루틴에 포함` 스위치, 선택한 운동 순서 목록과 `빼기`,
  운동 검색으로 추가, `루틴 수정`/`루틴 저장`, 기존 루틴이면 `이 루틴 삭제`까지 제공합니다.
- `RoutineCard`는 카드에서 바로 `추천 포함/제외` 스위치, `루틴 편집 ›`, `삭제`를 제공합니다.
  삭제는 `Alert` 확인 후 `state.routines`에서만 제거하고, 운동 기록·세션은 건드리지 않습니다.
- 홈 `나의 루틴` 카드도 추천 루틴을 먼저 보여 주고, 편집·삭제·추천 토글을 같은 방식으로 제공합니다.
- 홈 히어로의 `추천 루틴`과 `어떤 운동을 할까요?` 시트는 `recommendedRoutines()`를 씁니다. 모두 제외해도 안전하게 자유 운동으로 안내합니다.

**테스트** — `tests/routines.test.mjs`

- 기본 루틴은 추천에 포함, `recommended: false`와 예전 루틴(값 없음)의 처리, 모두 제외 시 빈 목록.
- 기본 루틴의 이름·운동·추천 여부 수정이 개수를 늘리지 않고 저장되는지, 새 루틴 이름 직접 입력과 기본 추천 포함.
- 삭제가 대상 루틴만 지우는지, 카드 토글이 순서·내용을 바꾸지 않는지, 이름·운동 누락과 40자 초과 거절, 백업 타입 검증.

## 버전 · 빌드

- `app.json`, `package.json`, `package-lock.json`(루트 2곳), `wearos/app/build.gradle.kts`(versionName), `watchos/project.yml`(MARKETING_VERSION)을 올렸습니다.
- **versionCode는 6으로 유지합니다.** `runtime-smoke.yml`의 페어 검사가 휴대폰 APK와 Wear APK의 `versionCode`·`versionName`이
  각각 `app.json`의 `android.versionCode`·`expo.version`과 같은지 확인합니다. 0.3.3까지도 6을 유지했으므로 같은 값으로 두고
  versionName만 0.3.4로 올립니다. (versionCode를 7로 올리면 `Build and verify the paired Wear OS package` 단계가 실패했습니다.)
- `release/v0.3.4` 브랜치를 `origin/main`(`8eda87d`)에서 만들었습니다. `Form native test release` 워크플로가
  `release/v*` 푸시에서 릴리스 5종(`Form-0.3.4-Android.apk`, `-Wear-OS.apk`, `-iOS-unsigned.ipa`, `-iOS-unsigned-watch.ipa`,
  `-SHA256SUMS.txt`)을 만듭니다.
