# Form 0.3.8 작업 기록 — 피클(Pickle) ↔ Form 양방향 연계 (2026-11-28)

모리 님의 지시로 만든 연계 릴리스입니다.

> "그냥 너를통해 운동입력도하고 오늘 운동에대한 피드백도 받을수있게끔"
> "그버전으로 업데이트해그럼" (자동 동기화까지 포함해 릴리스)

- 기준 커밋: `main` `07d1255` (v0.3.7)
- 릴리스 브랜치: `release/v0.3.8` (중간 프리뷰 브랜치 없음)
- 새 파일: `src/pickle-sync.mjs`(순수 로직), `tests/pickle-sync.test.mjs`, `sync/pickle-inbox.json`, 이 문서
- 고친 파일: `src/App.tsx`, `src/types.ts`, `src/storage.ts`, `app.json`, `package.json`, `wearos/app/build.gradle.kts`, `README.md`
- 새 네이티브 의존성: **없음**. `expo-linking`·`expo-clipboard`를 넣지 않고 React Native 기본 `Linking`·`Share`·`fetch`와 이미 쓰던 `expo-file-system`·`expo-sharing`·`expo-document-picker`만 씁니다. 딥링크는 `app.json`에 이미 있는 `"scheme": "form"`을 그대로 씁니다.

## 0. 한 장으로 보는 0.3.8

| 방향 | 사용자가 하는 일 | Form이 하는 일 |
| --- | --- | --- |
| 피클 → Form (자동) | 앱을 연다 | 앱을 열 때 `sync/pickle-inbox.json`을 한 번 읽어, 아직 반영하지 않은 항목만 `body`·`history`·`routines`에 병합하고 `피클에서 N건 반영됨` 띠를 4.5초 보여 줌 |
| 피클 → Form (링크) | `form://` 링크를 탭한다 | 종목·값을 검증해 미리보기 시트를 띄우고, `기록에 추가`/`루틴에 저장`/`체성분에 저장`을 눌러야 반영 |
| 피클 → Form (붙여넣기) | 내 정보 > 피클 연계에 링크나 JSON을 붙여넣거나 `.json` 파일을 고른다 | 링크와 같은 검증·미리보기 경로 |
| 피클 → Form (시작) | `form://start?routine=푸시 A`를 탭한다 | 그 루틴을 `준비 중 · 0:00` 화면으로 연다(타이머는 `운동 시작`을 눌러야 시작) |
| Form → 피클 | 기록 상세의 `피클에 보내기`, 또는 운동을 마친 직후 알림의 같은 버튼 | 세트·중량·RPE·메모·주간 볼륨·체성분을 한국어 브리핑 한 덩어리로 공유 시트에 넘김 (`피클용 JSON 저장`도 제공) |

핵심 원칙 네 가지:

1. **덮어쓰지 않습니다.** 백업 가져오기와 달리 운동 기록·루틴·체성분만 골라 병합하고, 같은 기록·같은 날 측정은 두 번 들어가지 않습니다.
2. **저장 전에 보여 줍니다.** 링크·붙여넣기는 미리보기 시트에서 확인을 받습니다. 자동 동기화는 사용자가 이미 피클에게 맡긴 항목이라 바로 반영하고 짧게 알립니다.
3. **값은 앱이 다시 검증합니다.** 피클이 보낸 중량·횟수·RPE·날짜·체성분을 `validateSession`·`validateBody`와 같은 규칙으로 다시 확인하고, 운동 이름은 도감 118종(+사용자 등록)과 맞춥니다.
4. **실패는 조용합니다.** 자동 동기화는 오프라인·주소 오류에서 아무 알림 없이 원래대로 동작하고, 항목 하나가 잘못돼도 나머지는 반영합니다.

## 1. 피클 → Form

### 1.1 딥링크

| 링크 | 하는 일 |
| --- | --- |
| `form://import-session?data=<base64url(JSON)>` | 완료된 운동 기록을 `history`에 추가 |
| `form://import-routine?data=<base64url(JSON)>` | 루틴을 `routines`에 추가/병합 |
| `form://import-body?data=<base64url(JSON)>` | 인바디·체성분을 `body`에 추가하거나 같은 날 기록을 갱신 |
| `form://start?routine=<루틴 이름 또는 ID>` | 그 루틴으로 준비 화면 열기 |
| `form://start?data=<루틴 JSON>` | 루틴 JSON을 저장하고 바로 준비 화면 열기 |

- 같은 데이터를 `?json=<URL 인코딩 JSON>` 또는 `form://import-session#<base64url>`로도 받습니다. 손으로 링크를 만들 때는 `?json=`이 편합니다.
- 경로 별칭: `session`·`record`(=import-session), `routine`(=import-routine), `body`·`inbody`(=import-body).
- 앱이 꺼져 있으면 콜드 스타트(`Linking.getInitialURL`), 실행 중이면 `url` 이벤트로 받습니다. 같은 링크가 두 번 들어와도 한 번만 처리합니다.

### 1.2 붙여넣기·파일

내 정보 > **피클 연계** > `피클에서 기록·루틴 가져오기`에서

- 받은 링크나 JSON을 **붙여넣기**(여러 줄 입력)
- `JSON 파일 고르기`로 `.json`/`.txt` 파일 선택

링크가 너무 길어 채팅에서 잘릴 때 쓰는 경로입니다.

### 1.3 병합·중복·검증

- 운동 기록: 맨 앞에 추가. 같은 `id`, 또는 같은 `startedAt`+같은 이름이 이미 있으면 **추가하지 않고** "이미 저장된 운동입니다"를 알립니다.
- 루틴: 같은 `id`면 내용 갱신(기존 운동 유지 + 새 운동 합침), 같은 **이름**이면 운동 목록을 합침, 없으면 새로 추가. 기존 루틴의 운동은 지우지 않습니다.
- 체성분: **같은 날(기기 달력 기준)** 기록이 있으면 그 기록의 `id`·사진·메모·건강 앱 동기화 표시를 유지한 채 값만 새로 고치고 `revision`을 1 올립니다. 새로 보낸 JSON에 없는 항목은 기존 값을 지우지 않습니다. 다른 날이면 새로 추가합니다.
- 운동 이름은 ① ID ② 도감 이름(띄어쓰기·괄호·대소문자 무시) ③ 짧은 별칭(`벤치`→바벨 벤치 프레스, `스쿼트`→바벨 백 스쿼트, `ohp`, `랫풀다운`, `푸시다운` 등) ④ 유일하게 걸리는 부분 일치 순서로 찾습니다.
- 여럿이 걸리면 후보를 보여 주고, 없으면 예시 이름 4개와 함께 알립니다. 이때는 아무것도 저장하지 않습니다.
- 가져온 기록은 `source: "pickle"`, `importedAt`이 붙고, 건강 앱 자동 내보내기는 하지 않습니다(기존 정책대로 기록 상세에서 수동 `건강 앱에 운동 내보내기`).

## 2. Form → 피클 (오늘 운동 피드백)

- 기록 탭 > 운동 기록 상세 > **피클에 보내기** — iOS/Android 공유 시트에서 `복사`를 고르면 피클 채팅에 그대로 붙여넣을 수 있고, 피클 앱이 텍스트 공유를 받으면 바로 그 앱으로도 보낼 수 있습니다.
- 같은 화면의 **피클용 JSON 저장** — 브리핑과 같은 내용을 JSON 파일로 넘깁니다.
- 운동을 마치고 뜨는 `오늘의 운동을 기록했습니다` 알림의 **피클에 보내기** — 세트를 끝낸 직후 한 번에 피드백을 요청하는 경로입니다.
- 최근 인바디 기록이 있으면 브리핑 끝에 체성분 한 줄이 함께 들어갑니다.

### 2.1 브리핑 예시 (실제 출력)

```
[Form] 11월 28일 (토) · 가슴·삼두
8세트 · 총 볼륨 2,951 kg · 52분
첫 기록 바벨 벤치 프레스 101.3 kg · 덤벨 숄더 프레스 32 kg · 트라이셉스 푸시다운 42 kg

■ 바벨 벤치 프레스 · 가슴
1세트 60 kg × 10회 · 워밍업
2세트 80 kg × 8회 · RPE 8
3세트 80 kg × 8회
4세트 82.5 kg × 6회 · RPE 9
메모: 마지막 세트 자세 유지
■ 덤벨 숄더 프레스 · 어깨
1세트 24 kg × 10회
2세트 24 kg × 9회
■ 트라이셉스 푸시다운 · 팔
1세트 30 kg × 12회
2세트 30 kg × 12회

이번 주 1/4회 · 주간 볼륨 2,951 kg
체성분 11월 27일 · 체중 78.4 kg · 골격근 36.2 kg · 체지방 16.1%

이 기록으로 오늘 운동 피드백과 다음 운동 계획을 부탁해.
```

- 볼륨은 워밍업을 뺀 완료 세트(중량×횟수) 합계입니다. `0 kg`처럼 재는 단위는 한 칸 띄우고 `8회`·`3세트`는 붙입니다(0.3.7 규칙 유지).
- 설정에서 무게를 `lb`로 쓰면 중량과 볼륨이 lb로 바뀌고, 저장된 kg 값은 그대로입니다.
- `피클용 JSON 저장` 파일은 다시 `import-session`에 넣으면 같은 기록이 됩니다(왕복 검증 테스트 있음). 앞부분:

```json
{ "type": "session", "app": "form", "schemaVersion": 1,
  "name": "가슴·삼두", "startedAt": "2026-11-28T10:00:00.000Z", "endedAt": "2026-11-28T10:52:00.000Z", "minutes": 52,
  "exercises": [ { "id": "bench", "name": "바벨 벤치 프레스", "muscle": "가슴", "type": "strength",
      "sets": [ { "weight": 80, "reps": 8, "kind": "normal", "rpe": "8" } ] } ],
  "summary": { "sets": 8, "volume": 2951, "weekCount": 1, "weekGoal": 4, "weekVolume": 2951,
      "prs": [ { "name": "바벨 벤치 프레스", "value": 101.3, "first": true } ] },
  "body": { "date": "2026-11-27T09:00:00.000Z", "weight": 78.4, "bodyFat": 16.1, "muscle": 36.2 } }
```

`summary`·`body`·`app`·`schemaVersion`은 피클이 읽는 참고 정보이고, 다시 가져올 때는 `type`·`name`·`startedAt`·`minutes`·`exercises`만 쓰면 됩니다.

## 3. 자동 동기화 — `sync/pickle-inbox.json`

피클이 저장소에 올려 둔 인박스를 앱이 읽어, 사용자가 말하지 않아도 기록이 들어가 있게 하는 경로입니다.

- 주소(기본): `https://raw.githubusercontent.com/M0lli2/form-fitness/main/sync/pickle-inbox.json`
- 캐시 우회: 앱이 `?t=<밀리초 시각>`을 붙입니다. 주소에 `?`가 이미 있으면 `&t=`로 붙입니다.
- 시점: 앱을 열 때 한 번(설정 `앱을 열 때 자동 동기화`가 켜져 있을 때) + 내 정보 > 피클 연계 > `지금 피클 동기화`.
- 주소 변경: 내 정보 > 피클 연계의 주소 입력 + `주소 저장`(입력 중에는 저장하지 않음).
- 결과: 반영 건수가 있으면 화면 위에 `피클에서 N건 반영됨`을 4.5초 보여 줍니다. 없으면 아무것도 띄우지 않습니다.
- 실패: 네트워크·HTTP 오류는 자동일 때 조용히 넘어가고, 수동일 때만 알림을 띄웁니다.
- 중복 방지: 반영한 항목의 `id`를 `state.appliedSyncIds`에 남기고(최근 200개), 다음 실행부터는 그 항목을 건너뜁니다.
- 항목 하나가 잘못돼도(없는 운동 이름 등) 나머지는 반영하고, 실패한 항목은 `appliedSyncIds`에 넣지 않아 다음 동기화에서 다시 시도합니다.

### 3.1 파일 형식

```json
{
  "version": 1,
  "note": "공개 저장소이므로 개인 정보는 넣지 않습니다.",
  "items": [
    {
      "id": "body-2026-11-28-inbody",
      "kind": "body",
      "createdAt": "2026-11-28T10:06:00+09:00",
      "payload": { "type": "body", "date": "2026-11-28", "height": 177, "weight": 73.7,
        "muscleMass": 33.9, "bodyFat": 18.7, "bodyFatMass": 13.8, "bmi": 23.5,
        "bmr": 1665, "visceralFat": 6, "inbodyScore": 78 }
    }
  ]
}
```

| 필드 | 규칙 |
| --- | --- |
| `version` | `1`만 받습니다. 없으면 1로 봅니다. |
| `items[]` | 배열. 배열만 있는 파일도 받습니다. |
| `items[].id` | 필수·문자열. 중복 방지 키입니다. 같은 항목을 고칠 때는 **id를 그대로** 두고 payload만 고치면 앱이 다시 반영하지 않습니다. 새 값은 새 id로 보냅니다. |
| `items[].kind` | `body`·`session`·`routine`. 없거나 다르면 payload 구조로 추정합니다. |
| `items[].payload` | 각각 4.1~4.3의 JSON과 같습니다. |
| `createdAt` | 참고용(표시하지 않음). |

### 3.2 지금 들어 있는 항목

`body-2026-11-28-inbody` — 2026-11-28 10:06 측정, 키 177 cm · 체중 73.7 kg · 골격근량 33.9 kg · 체지방률 18.7 % · 체지방량 13.8 kg · BMI 23.5 · 기초대사량 1,665 kcal · 내장지방 6 · 인바디 점수 78. 이름·연락처·회원번호는 들어 있지 않습니다.

> **공개 저장소 주의**: `M0lli2/form-fitness`는 Public이라 이 파일도 누구나 읽을 수 있습니다. 수치는 익명이지만 신체 정보 자체가 공개되는 셈이므로, 필요 없어지면 항목을 지우거나(빈 `items`) 주소를 비공개 위치로 바꾸는 편이 안전합니다. 파일을 지워도 이미 반영된 기록은 앱 안에 그대로 남습니다.

## 4. 스키마 명세 — 피클이 그대로 만들어도 되는 형식

### 4.1 운동 기록 `session`

```json
{ "type": "session", "name": "가슴·삼두", "date": "2026-11-28", "minutes": 52,
  "exercises": [
    { "name": "바벨 벤치 프레스", "note": "마지막 세트 자세 유지", "sets": [ { "weight": 80, "reps": 8, "rpe": 8 } ] },
    { "name": "플랭크", "sets": [ { "seconds": 60 } ] } ] }
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `type` | 권장 | `session`(`workout`·`record`·`log`도 가능). 없으면 `exercises`마다 `sets`가 있으면 기록으로 봅니다. |
| `name` | 아니오 | 40자 이내. 없으면 `피클 운동`. |
| `date` | 아니오 | `YYYY-MM-DD` → 그날 **19:00(기기 시간)** 시작. `startedAt`(ISO)이 있으면 그 시각, `endedAt`만 있으면 `endedAt − minutes`. 셋 다 없으면 지금 − minutes. |
| `minutes` | 아니오 | 1~1440 정수. 없으면 `max(10, 세트수×3)`. |
| `id` | 아니오 | 80자 이내. 없으면 이름·시작 시각·종목·세트 수로 만든 `pickle-…`(같은 데이터 → 같은 ID). |
| `exercises` | **예** | 1~40개, 같은 운동 중복 불가. |
| `exercises[].id`/`name` | 하나는 **예** | 도감 ID(`bench`) 또는 이름(`바벨 벤치 프레스`), 짧은 별칭 가능. |
| `exercises[].note` | 아니오 | 1,000자 이내. |
| `exercises[].sets` | **예** | 1~20개. `{ "weight": 80, "reps": 8 }`처럼 바로 넣어도 됩니다. |

세트: 중량 종목은 `weight` 0~1000(맨몸 0)·`reps` 1~1000 정수(필수)·`rpe` 1~10(선택), 시간 종목은 `seconds` 1~86400 또는 `minutes`. `kind`는 `normal`·`warmup`·`drop`. 짧은 형식 `[80, 8]`(중량, 횟수)·`[60]`(초)도 받습니다.

### 4.2 루틴 `routine`

```json
{ "type": "routine", "name": "푸시 A", "subtitle": "가슴·어깨·삼두",
  "exercises": ["바벨 벤치 프레스", "덤벨 숄더 프레스", "트라이셉스 푸시다운"] }
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `name` | **예** | 40자 이내 |
| `exercises`(또는 `ids`) | **예** | 1~20개. 이름·ID·`{ "id": … }`. 중복은 합칩니다. |
| `subtitle` | 아니오 | 없으면 `피클에서 보낸 루틴` |
| `recommended` | 아니오 | `false`면 홈 추천에서 제외 |

### 4.3 체성분 `body`

```json
{ "type": "body", "date": "2026-11-28", "measuredAt": "2026-11-28T10:06:00+09:00",
  "height": 177, "weight": 73.7, "muscleMass": 33.9, "bodyFat": 18.7, "bodyFatMass": 13.8,
  "bmi": 23.5, "bmr": 1665, "visceralFat": 6, "inbodyScore": 78, "note": "아침 공복" }
```

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `weight`(`bodyWeight`) | **예** | 20~400 kg |
| `date`(`measuredAt`·`at`) | **예** | `YYYY-MM-DD` 또는 ISO 8601. 둘 다 있으면 `date`를 씁니다. 미래 시각은 거부합니다. |
| `muscleMass`(`muscle`·`skeletalMuscleMass`·`smm`) | 아니오 | 1~150 kg, 체중보다 클 수 없음 |
| `bodyFat`(`bodyFatPercent`·`pbf`) | 아니오 | 0~75 % |
| `bodyFatMass`(`fatMass`·`bfm`) | 아니오 | kg. `bodyFat`이 없으면 체중으로 체지방률을 계산합니다. |
| `height`(cm) | 아니오 | 80~250. 있으면 BMI를 계산합니다. |
| `bmi` | 아니오 | 없으면 `체중 ÷ (키/100)²` |
| `bmr` | 아니오 | 300~5000 kcal |
| `visceralFat` | 아니오 | 1~30 레벨 |
| `inbodyScore` | 아니오 | 1~100 |
| `waist` | 아니오 | 30~250 cm |
| `note`(`memo`) | 아니오 | 2,000자 이내 |

받은 값은 `src/types.ts`의 `BodyEntry`(+`bodyFatMass`·`bmi`·`inbodyScore` 선택 필드)로 저장됩니다.

### 4.4 링크 만드는 법

1. 위 JSON을 만든다.
2. UTF-8 → base64url(패딩 `=` 없음).
3. `form://import-session|import-routine|import-body?data=` 뒤에 붙인다.

같은 링크를 `?json=` + `encodeURIComponent(JSON)` 으로도 만들 수 있습니다(짧은 JSON에 편함). 2종목 4세트 기록은 링크가 약 **680자**이고, 세트가 많은 날은 1,500자까지 늘어납니다. 채팅에서 잘릴 수 있으면 JSON 코드 블록 + 앱의 붙여넣기 경로를 안내합니다.

### 4.5 오류 문구

| 상황 | 앱이 보여 주는 것 |
| --- | --- |
| 모르는 경로 | `알 수 없는 피클 링크입니다. (경로)` |
| 데이터 없음/깨짐 | `링크에 담긴 기록을 읽지 못했습니다. (…)` |
| 운동 이름이 여럿 | `'컬' 운동이 여러 개입니다(…). 정확한 이름이나 ID로 다시 보내 주세요.` |
| 운동 이름 없음 | `'없는운동' 운동을 운동도감에서 찾지 못했습니다. 예: …` |
| 범위 오류 | `바벨 벤치 프레스 1세트 횟수: 1~1000 범위로 보내 주세요.` / `체성분 값을 확인해 주세요. …` |
| 같은 운동 두 번 | `바벨 벤치 프레스 운동이 두 번 들어 있습니다. 한 번으로 합쳐 보내 주세요.` |
| 종류 불일치 | `운동 기록이 아닌 데이터입니다…` / `루틴이 아닌 데이터입니다…` / `체성분 기록이 아닌 데이터입니다…` |

## 7. 남은 확인 사항

- 실기기에서 ① `form://` 링크 탭 → 미리보기 → 저장, ② 앱 첫 실행 시 `피클에서 1건 반영됨`과 인바디 값(73.7 kg · 33.9 kg · 18.7 %) 확인이 필요합니다. 자동 동기화는 `main`에 이 파일이 올라간 뒤부터 동작합니다.
- iOS가 앱을 꺼 둔 상태에서 링크를 열 때도 `Linking.getInitialURL` 경로를 씁니다.
- 공유 시트에 피클 앱이 텍스트 공유 대상으로 뜨는지는 기기에 설치된 피클 앱의 공유 확장에 달려 있습니다. 뜨지 않으면 `복사` 후 붙여넣으면 됩니다.
- 카카오톡·텔레그램이 `form://` 스킴을 링크로 인식하지 않는 경우가 있습니다. 그때는 앱의 붙여넣기 경로나 JSON 붙여넣기를 씁니다.
- `sync/pickle-inbox.json`은 공개 파일입니다. 수치를 공개로 두지 않으려면 항목을 비우거나 `pickleSyncUrl`을 비공개 위치로 바꿉니다.
